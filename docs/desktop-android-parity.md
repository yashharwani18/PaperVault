# Desktop-to-Android parity audit (in progress)

This is an evidence ledger, not a claim of completed parity. Source code is authoritative; existing README test statements are historical and have not been independently rerun for this mission.

| Capability | Windows implementation | Android implementation | Assessment / next action |
|---|---|---|---|
| Formats | `knowledge_library/text_documents.py`, `pdf.py`, `presentations.py`: text, office formats, PDF/PPTX | `DocumentReader.java` and Office/plain-text parsers: PDF/PPTX/DOCX/XLSX/TXT/MD/CSV/TSV; `PhoneScan.java` discovers PDFs | Manual text formats are implemented but require device validation; phone discovery remains PDF-only. |
| Chunking and text coordinates | `chunking.py`: tokenizer offsets and page-contained overlap | `PageIndexer.java`: token-bounded natural boundaries and overlap | Similar goals, not demonstrated equivalent; compare on common corpus. |
| Embeddings and cache | `embedding.py`, `library.py`, `retrieval.py`: normalized vectors, cache, bounded snapshot | `LiteRTTextEmbeddings.java`, `PageIndexer.java`, `AndroidEmbeddingUpgrade.java`: INT4 LiteRT model, cached batching and shadow migration | Different model/runtime identity; measure quality and device resources before changing configuration. |
| Content retrieval | `retrieval.py`: SQLite FTS, semantic ranking, optional RRF; `server.py` exact passage priority | `NativeBackend.search`, `LiteralSearch.java`: semantic ranking and exact passage scan | Both have literal and semantic retrieval, but Android scans text and lacks calibrated fusion. A shared UI now calls platform metadata-only exact filename endpoints before inference; the backend `/search` path also returns exact filename matches before inference, with a content-only option. |
| Local query understanding | `query_interpreter.py`: Qwen subprocess, constrained schema and validation | `NativeBackend.interpretSearch/interpretAmount`: Qwen local, constrained fields | Both call Qwen on searches in current source; compare multilingual results and adaptive routing. |
| Bills | `bills.py`, `bill_amounts.py`: extracted/saved fields, aliases, amount matching | `Money.java`, `NativeBackend` bill handlers: amount fields, aliases and evidence | Similar support, unproven parity for Gujarati, ambiguity and OCR. |
| Source navigation | `search_previews.py`, `ContinuousPdf.tsx`, text viewer and citations | native page/word evidence, shared PDF viewer and citations | Filename-only hits and multi-page navigation need explicit validation. |
| Metadata and organization | `organization.py`, `workspace_features.py` and shared UI | `LibraryQoL.java`, `KhojFeatures.java`, `PhoneScan.java` | Favorites/recent and revision-aware PDF positions now exist on both platforms. Shared UI supports sorting, filtering, alphabet jumps and 100-row pages; database-backed paging and fully indexed metadata queries remain incomplete. |
| Resilience | Atomic indexing and SQLite snapshot; discovery/recovery tools | persisted tasks, scan signatures, checkpoint and resumable model upgrade | Verify interrupted imports, permissions and existing-library migrations on device. |
| Scale/UI | `/state` exposes all documents; `App.tsx` filters, sorts and maps rows in browser | same shared UI and state pattern | The UI now renders at most 100 library rows per page and polls less often when idle. The state API avoids retransmitting unchanged catalogs but still builds and initially transfers the full catalog; client-side sorting/filtering remain; database-backed paging and measurement are still required. |
| Builds | Existing bundled Windows prototype and separate compiled installer | signed full APK; no currently connected device | Need rebuild after changes and actual phone/emulator test; existing output is not proof of current functionality. |
