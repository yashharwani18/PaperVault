# Offline retrieval upgrade: controlled first experiment

User approved proceeding after the research recommendation. Preserve build 21's structured bill routes and offline Android behavior. First measure the existing Android model on a fixed public corpus; do not add a reranker or change shipped ranking merely because a technique is popular.

Compare the current semantic recipe (original query concatenated with Qwen rewrite) against original-query-only dense retrieval, BM25, and page-deduplicated reciprocal-rank fusion. Optionally fuse original and rewritten query rankings separately. All candidates use identical source-page text, Android PageIndexer chunks and actual LiteRT embeddings. No new model weights are needed for this first experiment. A neural reranker is a subsequent experiment if candidate retrieval improves and phone costs are acceptable.

Use the existing 20-public-PDF Phase 3 corpus and frozen source-page judgments, plus prewritten Hindi translations that inherit their parent's dev/test split. PyMuPDF supplies identical source text to all candidates; this is a retrieval experiment, not a comparison of PDF extraction/OCR. These development-era judgments are diagnostic and not a new independent benchmark.

Choose a candidate on development queries only. Frozen candidates: original-only; current combined-query; RRF original+BM25 and combined+BM25 at semantic weights .5/.75 with rank constant 60; separate original/rewrite/BM25 at equal weights. Deduplicate physical pages before fusion so long pages cannot vote repeatedly. Select by Recall@3, then Recall@5, then MRR@5, preferring the simpler/faster recipe on ties. Score the test split once after saving the selection. Candidate promotion requires test Recall@3 improvement of at least .02, no lower Recall@5, no lower English or Hindi Hit@5, and no increase in no-answer candidate-return rate. Report no-answer scores separately; do not call relevance similarity a correctness probability.

Measure source indexing, generation, query embedding and rank-only time separately. Desktop ablation timing is not Android end-to-end latency. A ranking win must also pass an actual Android latency check and all existing bill regressions before shipment. If nothing passes, retain build 21 and report the failed experiment.

Sources: Microsoft hybrid RRF documentation; Sentence Transformers retrieve-and-rerank documentation; Anthropic contextual retrieval report; BEIR evaluation paper. Contextual text must be source-derived when applied to financial documents. Hindi support, licensing and Android runtime/memory cost must be verified before adopting a new reranker.

Evaluator details locked before ranking: baseline keeps the best 20 chunks before page deduplication, matching build 21. Original-only uses the same cap; an additional combined-query/page-deduplicated candidate isolates that cap's effect. Hybrid candidates use 100 unique pages per ranker. BM25 uses SQLite FTS5 unicode61 on original-query terms, OR matching, fixed stop words and text/title weights 1.0/.3. Separate-query fusion uses original dense, rewrite dense and original-query BM25 at equal weight. No stemming, learned reranking or rejection threshold is introduced in this experiment.
